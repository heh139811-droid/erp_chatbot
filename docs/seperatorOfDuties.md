# ERP 권한 정리

> 지금 ERP에 실제로 들어 있는 권한을 업무 용어로 정리한 것.
> 관련: [[챗봇 초안]]
>
> **ERP 챗봇 1차 목표에서는 권한 분기를 구현하지 않는다.** 권한 정책이 계속 바뀔 수 있으므로 이 문서는 2차 목표 착수 시점에 다시 확인하고, 당시 확정된 정책을 기준으로 적용한다.

---

## 1. ERP에 있는 역할 11개

| 역할              | 무엇을 하는 사람인가                                             |
| --------------- | ------------------------------------------------------- |
| **개발팀 관리자**     | 시스템 설정 담당. 역할 부여·회수, 전사 조회자 지정, 상품 등록, CRM 연결, 감사 기록 확인 |
| **경영진** (대표·이사) | 업무 데이터 전권                                               |
| **인사 담당자**      | 직원 소속·직무 승인, 직원 일반 정보 관리                                |
| **본부장**         | 본부 책임자                                                  |
| **팀장**          | 팀 책임자. 파트장도 팀장과 같다                                      |
| **영업 담당**       | 직무                                                      |
| **재무 담당**       | 직무                                                      |
| **마케팅 담당**      | 직무                                                      |
| **디자이너**        | 직무                                                      |
| **영상 담당**       | 직무                                                      |
| **전사 업무 조회자**   | 따로 지정받은 사람. 전사 계약을 조회할 수 있다 (수정은 못 한다)                  |

### 알아둘 점

- **직급은 권한이 아니다.** 선임·책임이어도 권한이 더 생기지 않는다.
- **역할에는 기간이 있다.** 적용일 전이거나 만료된 역할은 효력이 없다.
- **조직이 바뀌면 그 조직에 붙은 역할이 자동으로 없어진다.** 팀장이 다른 팀으로 옮기면 전 팀 팀장 권한이 사라진다.
- **유닛 소속은 권한과 무관하다.** 유닛은 협업 조직일 뿐이고, 권한도 티켓 수신 대상도 아니다.
- **승인 전 직원은 로그인은 되지만 업무를 보지 못한다.** 인사 담당자가 소속·직무를 승인해야 한다.
- **권한은 화면을 볼 때마다 다시 확인한다.** 역할을 회수하면 즉시 반영된다.

## 2. 권한이 정해지는 4가지 방식

ERP에서 "이 사람이 이 자료를 볼 수 있나"는 아래 네 가지 중 하나로 정해진다.

### ① 전권인가
개발팀 관리자와 경영진은 대부분을 본다.

### ② 나와 관계가 있는 일인가
내가 보낸 것, 나한테 온 것, 내가 참여한 것, 내가 만든 것.
**티켓이 대표적이다.** 티켓은 메일과 같아서 **받은 사람만 본다.**

### ③ 내 조직 것인가
내가 소속된 팀, 내가 관할하는 팀, 내 본부.

### ④ 내가 담당인 고객인가
고객마다 **(고객 + 팀 + 직무)** 로 담당이 지정된다.
예: A고객의 영업 담당 = 1팀 홍길동, A고객의 마케팅 담당 = 2팀 김철수

**중요: 담당으로 지정됐더라도 그 직무 역할을 본인이 갖고 있어야 한다.**
영업 팀장이 팀원의 재무 자료를 보려면 본인에게 재무 담당 역할도 있어야 한다. 팀장이라는 사실만으로 팀원의 모든 자료가 열리지 않는다.

## 3. 자료별로 누가 보는가 ★

| 자료                  | 누가 보는가                        | 팀장이 더 보는 것              | 본부장이 더 보는 것   |
| ------------------- | ----------------------------- | ----------------------- | ------------- |
| **티켓 (업무 요청)**      | 보낸 사람 + 받은 사람(사람·팀·본부 수신)     | **없음**                  | **없음**        |
| **할 일**             | 본인 할 일은 본인만. 팀 공개 할 일은 그 팀 사람 | 본인이 **소속된** 팀의 팀 공개 할 일 | 없음            |
| **프로젝트**            | 만든 사람·책임자·참여자로 지정된 사람         | 없음                      | 없음            |
| **보고서**             | 작성자·받는 사람·공유받은 사람             | 없음                      | 없음            |
| **고객 이름·브랜드·현재 담당** | 전 직원                          | —                       | —             |
| **고객 연락처·메모·재무**    | 그 고객의 담당                      | 관할 팀의 담당 건              | 없음            |
| **계약**              | 그 고객의 담당                      | 관할 팀의 담당 건              | **전사 전체**     |
| **개인 가망 고객**        | 등록한 본인                        | 관할 팀 사람이 등록한 것          | 없음            |
| **영업 통화·일일 콜 기록**   | 담당                            | **자기 팀만**               | 없음            |
| **취급고 집계**          | 본인 담당분                        | 관할 팀                    | 계정별 일별 요약은 전사 |
| **자료실 파일**          | 그 고객의 담당 (영업·마케팅·디자이너·영상·재무)  | 관할 팀의 담당 건              | 없음            |
| **제작 요청**           | 요청자·담당자·작업 참여자                | 없음                      | 없음            |

## 4. 오해하기 쉬운 3가지

### ① 티켓은 팀장도 팀원 것을 보지 못한다
티켓은 조직 기준이 아니라 **메일처럼 수신 기준**이다.
팀장이 팀원의 티켓을 보려면 그 티켓이 팀으로 수신됐거나 팀장 본인이 수신자여야 한다. "내 팀원 것이니 다 본다"는 규칙이 없다.

### ② 본부장은 계약만 전사다
- **계약** → 담당자가 누구든 **전사 전체**를 본다. (금액·상품 가격·수수료 포함)
- **그 외** (티켓, 할 일, 고객 연락처, 자료실, 제작, 가망) → **추가 권한이 전혀 없다.** 일반 직원과 같다.

본부장에게 주는 전사 계약 조회는 수정 권한이 아니다. 관계 밖 고객의 개인정보·재무 메모·원본 파일·직원 평가는 여전히 못 본다.

### ③ "팀장 범위"가 자료마다 다르다
| 자료 | 팀장 범위 |
|---|---|
| 할 일 | 본인이 **소속된** 팀 |
| 영업 통화·일일 콜 | **자기 팀만** (관할 팀 포함 안 됨) |
| 고객·계약·자료실·가망·취급고 | **관할 팀 전체** (웍스에서 하위에 있는 팀까지) |

## 5. 전권이어도 못 보는 것

개발팀 관리자·경영진도 아래는 못 본다.

| 대상 | 누가 보는가 |
|---|---|
| **티켓 숨은 참조 목록** | 요청자(보낸 사람)만 |
| 타인의 **개인** 할 일 | 개발팀 관리자만 |
| 제출된 보고서 | 개발팀 관리자만 |
| 시스템 설정 (역할 부여, 전사 조회자 지정, 상품, CRM 연결, 감사 기록) | 개발팀 관리자만 |

숨은 참조는 담당자·부서장·일반 참조도 **존재조차** 알 수 없다.

## 6. 티켓 수신 규칙 (별도 정리)

티켓 권한이 가장 복잡하므로 따로 적는다.

| 수신 방식 | 누가 보는가                        |
| ----- | ----------------------------- |
| 사람 To | 그 사람 (= 담당자). 소속이 바뀌어도 계속 본다  |
| 팀 To  | 그 팀의 **현재** 구성원. 팀에서 빠지면 못 본다 |
| 본부 To | 본부와 하위 조직의 현재 구성원 전원          |
| 참조    | 열람·댓글만. 상태·담당·수신은 못 고친다       |
| 숨은 참조 | 열람만. 댓글 못 씀. 요청자만 명단을 본다      |
| 유닛    | **수신 대상이 아니다**                |
|       |                               |

- 사람 To가 하나라도 있으면 상태는 `담당자 배정완료`, 부서만 있으면 `부서 확인요청`.
- 부서 구성원은 **자기 원소속 팀 사람만** 담당에 넣을 수 있다. 타팀 사람은 못 넣는다.
- 전달·수신 수정은 요청자·담당·부서장만 한다.
- 부서장은 그 수신 조직의 정확한 팀장/본부장이다. 본부 티켓의 부서장은 본부장뿐이고, 하위 팀장은 일반 부서원이다.
- 회수하면 요청자만 남는다.

## 7. 확인이 필요한 것 1건

문서에는 "경영진은 다른 직원의 개인 할 일과 제출 보고서를 개발팀 관리자와 똑같이 본다"고 되어 있는데, 실제 ERP는 **개발팀 관리자만** 보게 되어 있다. 경영진은 자기와 관계있는 것(본인이 작성·수신·공유받은 것)만 본다.

문서 쪽이 더 넓은 방향이라 정보가 새는 상황은 아니다. 어느 쪽이 맞는지 확인이 필요하다.
